# Murder analysis

Use the phase playbook; initial extraction records literal harm observations only. Classify each signal as in-world, historical/quotation, metaphor/idiom or unclear. The printed word “dead” does not establish a story-world murder.

For an apparent in-world event, distinguish four propositions with separate C IDs: **death occurred**, **death resulted from intentional killing**, **victim identity**, **perpetrator identity**. Unknowns remain unresolved. Means, motive, opportunity and narrative self-implication can support different propositions without proving them all. Cite exact layer-aware V evidence, dependencies, alternatives, falsifiers and tests; use descriptive support standards, never numerical confidence increments.

Maintain `State/events.jsonl` under the canonical schema and link it from cast/confidence views. An event ID denotes one hypothesized event, not one page mention. Before adding another, compare time, participant, means and consequences with existing events; merging event descriptions or entity aliases requires explicit support. Different labels for the same person do not create distinct victims.

Keep attempts, illness and allusive deaths distinct from completed intentional killings. A person can be both murderer and victim; do not assume disjoint roles. The six/six puzzle target checks a supported result, never licenses filling empty slots. If the evidence supports fewer or more, leave the discrepancy visible and test identities or event deduplication.

Final participation claims must be strongly constrained with current dependencies and discriminating tests under the final gate. If literal versus quoted death remains unclear, retain an unresolved event or research question, not an accusation.
